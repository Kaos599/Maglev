# Feature map

Every user-facing feature, where its code lives, the states it moves through, and whether it has a model. This is the backlog for models: each feature should get a state machine and a TLA+ model over time. Pick one from [Models wanted](#models-wanted), read [state-machines.md](state-machines.md), and open an issue saying which one you're taking.

How to read the columns:

- **States** are the names the code uses (type unions, enums, reducer kinds), with the file that defines them. "No named states" means the feature runs on booleans or plain values.
- **Model** is the folder under `specs/` with a TLA+ model that `npm run models` checks, or "none".
- **Checks** are the scripts and Maestro flows that cover the feature. A `test-…` name is `node scripts/test-….js`; `npm test` runs the ones listed in the `test` script in `package.json`. The search and assistant suites run separately (`npm run test:search`, `npm run test:assistant`), and `npm run test:update` covers `test-update`, `test-update-native` and `test-ux-027`. A `.yaml` name is a flow in `.maestro/`. [testing.md](testing.md) explains each one.

Paths are shortened: `KT/` is `modules/maglev-engine/android/src/main/java/com/maglev/engine/`, `RS/` is `native/maglev-core/src/`, `TYPES` is `modules/maglev-engine/src/MaglevEngine.types.ts`.

## Models wanted

Ranked by risk: what breaks when Android kills the process, what two things can race, how many of the user's downloads are lost, and what an attacker could do. Take the top one that nobody is working on.

| # | Feature | Why it's risky |
|---|---|---|
| 1 | Link downloads | Restarts drop cookies and signed links (`needs_link`), and Kotlin auto-retry runs beside user retries; the Rust machine is unit tested per row, but nothing checks every path through it. |
| 2 | Free space and admission | Two adds at the same moment can both pass the check, and TS and Kotlin hold the same rule twice; a wrong answer fills the phone mid-download. |
| 3 | In-app updates | It installs code: the checks on hash, package, version and signer must all hold on every path, including one restored after process death or started from a notification. |
| 4 | Found files and the download handoff | Recent fixes were races between page loads, the https fallback and the found list; a wrong order starts a download the user didn't tap, or loses one they did. |
| 5 | Lists that update themselves | It feeds search sources and trackers from the network; the signature and the rollback rule (`serial`) must hold for every order of checks and failures. |
| 6 | Actions the assistant proposes | The assistant acts for the user; a card or plan must never run after it expired, was dismissed or lost its target. The reducers exist; the model would check them. |
| 7 | Video sites | yt-dlp is code downloaded at runtime, and the link refresh lives in memory, so process death drops it. |
| 8 | Watches | A background JS task with a time budget; a source outage must never read as "nothing new". |
| 9 | Feeds and auto-download | The rule matcher and the "seen" sets exist in TS and Kotlin; drift adds an episode twice or never. |
| 10 | Share into Maglev | Partly done: [`specs/share-handoff/`](../specs/share-handoff/) covers start-up routing. The in-memory queue of a multi-item share is still unmodelled and is lost on process death. |
| 11 | Subtitles requests | Requests survive restarts by rewriting `searching` to `queued`; an epoch guard drops stale runs. Lower risk: a lost request costs a retry. |
| 12 | Search sources | Source health is in memory and resets on restart. Lowest risk: the worst case is a slow search. |

## Keeping this page true

- A PR that adds a feature adds a row. A PR that adds or renames a state updates the States cell.
- A PR that adds a model changes "none" to the `specs/` folder and takes the feature off Models wanted.
- [engine-boundary.md](engine-boundary.md) holds the engine's states in full; this page names them so you can find the code.
